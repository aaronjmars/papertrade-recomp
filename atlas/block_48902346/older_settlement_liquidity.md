# First older Exchange available LP and fee boundary

The first older Exchange delegates settlement to the pinned 5,873 byte library at `0xac8ba1307815f74bd13d4d039c96f7b97e81aa49`, SHA-256 `86184c390d6f62a8bd0e97080a0959ba7a3860b1358635994f82f61e81ceac8c`. Its seven-word selector `0xaa31b143` is reached in [136 sampled historical closes](older_exchange_library.md), and those 136 sampled calls use equal 2% gain and loss fee rates and ample liquidity.

The [historical getter capture](../../artifacts/deployer_scope/older_settlement_liquidity_getter.json) identifies the seventh input: transaction `0xe1d903a527ed571e938719d6c16a6580ba699dd9afbc6ca5bf4c1f651ae1be27` was first in block 47,572,843. Its library input is exactly the older Exchange's archived `lpBankrollAvailable()` return at block 47,572,842: `4738415954401651736665154` internal units. The saved block hash anchors that prestate. The same archived state also matches the old Exchange `stakerFeeAccumulator()` and `devFeeAccumulator()` getters to the low and high halves of storage slot 26. This equality alone does not establish every caller branch, so the fork replay also checks that changing the getter by a controlled treasury-slot override changes the library argument one-for-one.

A [separate historical verifier](../../scripts/atlas_older_settlement_history.py) checks a successful signed close in transaction `0xc8746368be8bddb68c528f67e18a3d80ad2a113479e47db4dfe006721c7c3e3c`, first in block 42,770,131. The archived prestate `lpBankrollAvailable()` value is zero while `totalQueued()` already contains `21,157.419962628282845447` internal units. The treasury exceeds ordinary balance, locked margin and fee reserves by `23,596.208841787750681761` internal units. Zeroing only global queue slot 18 in an archived read-only call changes the available getter from zero to that positive amount. The zero value is therefore the queue gate in this tested state, not proof that treasury funds were absent. Its deployed library call returns the 1-unit margin, zero immediate gain, and the full `0.000903710753436144` unit adjusted profit as queued. The receipt emits `Enqueued` for node 8,452. A transaction-level storage diff agrees: user and global queue totals each rise by that profit, the user balance rises by the margin, packed locked margin falls by the margin, and fee slot 26 is not written. The [raw capture](../../artifacts/deployer_scope/older_settlement_historical_enqueue.json.gz) includes the transaction, receipt, call trace, storage diff, archived getter and historical code. All three historical proxy, implementation and library runtime hashes match the pin. This proves that the zero-available, queue-gated branch executed once in the checked history.

A separate [full local transaction replay](../../scripts/audit_older_queue_close_replay.py) loads the archive prestate and all 11 captured contract runtimes, each matching the pinned code. It submits the original BatchExecutor calldata with the observed BBO response supplied at precompile `0x080e`. All six receipt logs and all 13 changed contract storage words match the archived transaction. The [replay ledger](../../artifacts/deployer_scope/older_settlement_historical_replay.json), [prestate](../../artifacts/deployer_scope/older_settlement_historical_prestate.json.gz), and [block header](../../artifacts/deployer_scope/older_settlement_historical_header.json) make this check reproducible offline. The replay does not check the sender nonce or Core settlement, and one transaction does not establish the full history of low-liquidity closes.

The [replay generator](../../scripts/atlas_older_settlement_liquidity.py) runs [nine direct library tests](../../artifacts/deployer_scope/older_settlement_liquidity.t.sol) and [five full Exchange fork tests](../../artifacts/deployer_scope/older_settlement_exchange.t.sol). The direct tests use the exact library runtime in a delegatecall harness with an empty queue. They check all six return words, queue storage and `Enqueued` topics. The fork tests start from the saved block 47,721,328, use signed open and close calls through the actual Exchange and SessionKeyManager runtimes, and set a controlled close price. They vary treasury slot 14 after the open, check the Exchange's `lpBankrollAvailable()` getter, then verify user balance, global and user queue totals, and the two fee accumulator lanes after close. [Saved call traces](../../artifacts/deployer_scope/older_settlement_exchange_trace.txt.gz) and [case ledgers](../../artifacts/deployer_scope/older_settlement_exchange_replay.json) record the executed library arguments and returns.

For the constructed profitable close, adjusted profit `P` is `0.331156061910525405` internal units and the 2% fee `F` is `0.006623121238210508`. The close returns the 25-unit margin in every case:

| Available LP bankroll at settlement | Profit credited now | Profit queued | Fee recorded |
|---:|---:|---:|---:|
| 0 | 0 | 0.331156061910525405 | 0 |
| `P - 1` internal unit | 0.331156061910525404 | 1 internal unit | 0 |
| `P` | 0.331156061910525405 | 0 | 0 |
| `P + F - 1` internal unit | 0.331156061910525405 | 0 | 0 |
| `P + F` | 0.324532940672314897 | 0 | 0.006623121238210508, split equally |

Within the tested values, the branch is `available >= P + F`: it credits `P - F` and records the fee. Otherwise it credits up to `min(P, available)`, queues the remainder, and records no fee. A one-unit increase from `P + F - 1` to `P + F` therefore reduces the user's immediate credit by `F` and increases fee accrual by `F`. Direct library tests with unequal rates also show that profitable settlement uses the gain rate while a loss uses the loss rate even when available bankroll is zero. This corrects the earlier model's untested zero-available assumption for the first older library; it does not change the 136 sampled historical matches under ample liquidity. Guardian [L-10](../../artifacts/guardian_papertrade_report.html#l-10) records the team's acceptance of a queue-live fee waiver in a different same-batch path. The saved older close above begins with an existing queue; the fee-threshold fork cases are constructed.

This is a reproducible fee and queue discontinuity in a constructed archive fork, not proof of a security exploit. The signer authorization and close price are constructed, and the treasury slot is overridden to reach the boundary. One zero-available branch occurred historically during a queue backlog, but we have not shown that an unprivileged actor can force the tested fee threshold, that the resulting queue is always redeemable, or that a Core transfer would settle. It is not listed as a new finding. Other rate, margin and queue states remain open.
