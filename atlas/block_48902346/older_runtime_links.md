# Older implementation and linked-library comparison

The [offline verifier](../../scripts/atlas_older_runtime_links.py) checks the older direct-creation bytecode from the pinned deployer capture and [three additional linked-library runtimes](../../artifacts/deployer_scope/older_linked_libraries.json.gz) fetched at block 48,902,346. Six older direct-runtime SHA-256 hashes are absent from the newest 25-address manifest. Four differences reduce to exact link-address or metadata substitutions; the two remaining code bodies are the first earlier Exchange and a multisig runtime shared by both older sets.

| Older direct runtime | Pinned relationship to newest suite |
|---|---|
| First earlier Exchange implementation, 22,954 bytes | Different code and 96 dispatched selectors versus 98 in the newest Exchange. Links an additional 5,873-byte Exchange library at `0xac8ba1307815f74bd13d4d039c96f7b97e81aa49`. Its owner pending-sweep clear is [tested separately](older_exchange_clear.md). |
| First earlier Tokenomics implementation, 3,324 bytes | The only byte differences are two `PUSH20` operands linking its math library at `0x3c69230dfaf54e0b70f11134429c7ca4e2f11321`. Replacing those operands makes the runtime byte-identical to both the second earlier and newest Tokenomics implementations. |
| First earlier BatchExecutor implementation, 3,451 bytes | Only the 32-byte IPFS digest in Solidity metadata differs. The executable bytecode and remaining metadata bytes equal the second earlier and newest implementations. |
| Older multisig, 2,713 bytes, used by both earlier sets | Identical across the two earlier sets. Its 11-selector dispatcher differs from the newest 3,134-byte multisig's 13-selector dispatcher. The [older governance capture](older_governance.md) tests one historical execution family; other multisig functions remain to reconstruct. |
| Second earlier original Exchange implementation, 23,052 bytes | Ten `PUSH20` library operands differ from the newest Exchange. Zeroing those operands makes the entire runtime byte-identical to the newest implementation. This original implementation is no longer installed behind the second earlier Exchange at the pin. |
| Second earlier Tokenomics implementation, 3,324 bytes | Only two `PUSH20` operands differ, linking its math library at `0x261a4113a9bced5d545f8edd340cc9c81dc96c94`. The normalized runtime is byte-identical to the newest Tokenomics implementation. |

Both older math-library addresses hold the exact same 585-byte runtime SHA-256 as the newest math library. The second earlier original and pinned Exchange implementations link `0x5a4bda2dcc82749258d9e5cdd49cd52c3cd16388`, already in the newest manifest as a variant library. That runtime and the newest live Exchange library differ only at the 20-byte self-address embedded in the library guard. The first earlier Exchange library is different: it has 11 dispatched selectors versus ten in the later libraries, with two old-only selectors and one later-only selector. Its [older-only close settlement and queue paths](older_exchange_library.md) now have 24 historically checked position calculations and five constructed queue cases; other branches still need reconstruction. The second earlier Exchange's **pinned** replacement implementation differs from the original and newest runtimes. A [fourteen-case exact-runtime comparison](older_exchange_variant.md) establishes a 1 USDC reserve on spot retries, a full-balance first request at the 10 USDC minimum, and a separate below-minimum pending clear path. Other replacement paths remain outside the detailed behavior audit.

Byte identity after replacing linked addresses proves identical remaining bytes, not identical contract state, target identity, or behavior after a different external call result. The captured bytecode confirms these three extra library addresses hold code at the pin. Their deployers have not been traced. A [separate archive trace](older_exchange_upgrade.md) identifies the second earlier Exchange's move to its pinned replacement, but complete upgrade histories remain open. No whole-suite audit conclusion follows from the normalization alone.
