# Older Exchange locked margin at block 48,902,346

The [position verifier](../../scripts/atlas_older_positions.py) uses the complete, contiguous older Exchange [event captures](older_accounts.md) from each proxy's creation through the pinned block. It treats `PositionOpened` as an opening record and the two position-ID topics observed in each set as terminal records. For every terminal record, the position ID was opened earlier, the indexed user matches the opening user, and no position ID opens or terminates twice. Open IDs are exactly `0` through `nextPositionId() - 1` in both sets. The first earlier Exchange's terminal event signature preimages are still unverified, so the reconciliation relies on their observed position-ID and user relationship, the checked close path, and storage samples rather than assigning source event names to both topics.

The first set's terminal topics have 211,365 and 167,303 records. The second set has 48,877 `PositionClosed` and 2,945 `Liquidated` records. Every count comes from saved raw logs, with no event-page limit. The locked-margin and queued getters match raw Exchange storage slots 22 and 18 at the pinned block. `nextPositionId()` matches raw slot 11 and the number of unique opens. The separately captured `totalBalances()` and `treasury()` values also match raw slots 22 and 14.

The saved [first-set](../../artifacts/deployer_scope/older_exchange_0_positions.json.gz) and [second-set](../../artifacts/deployer_scope/older_exchange_1_positions.json.gz) archive captures check the two position storage words at mapping base 10 for 318 first-set and all 12 second-set remaining positions. The first-set sample includes 256 IDs spread across its remaining ID range plus the 64 largest opening margins, with overlap removed. For every checked position, the stored user, instrument, side, entry price, margin, and leverage match its opening event, and the active bit is set. A separate 64-ID spread sample from each set's terminal records retains its opening margin but has the active bit cleared. The first-set active storage sample represents 2,497,521.122738205739400438 internal units of its 27,815,598.618510431633825980 total.

This reconciles the event-derived position margin to each global locked-margin field, alongside the [ordinary balance reconciliation](older_accounts.md). It does not inspect every first-set position storage word or every terminal position word, rule out unlogged storage mutations, identify every other claim type, or establish redeemability or USDC backing. The separate [queue reconciliation](older_queue_claims.md) checks all users observed in older enqueue events, but does not rule out unlogged queue writes for other addresses. The internal accounting units should not be described as user-redeemable USDC without separate settlement evidence.

Run `python3 scripts/atlas_older_positions.py` for offline verification using saved evidence. To recapture pinned getter and position storage samples, set `PAPERTRADE_ARCHIVE_RPC` to an archive HyperEVM RPC URL and run `python3 scripts/atlas_older_positions.py --capture-set 0` and `--capture-set 1`.
