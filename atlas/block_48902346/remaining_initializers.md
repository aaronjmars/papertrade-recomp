# Four previously unindexed initialization paths

Seven assertion-bearing Forge tests install the exact pinned proxy and implementation runtimes for Staking, SessionKeyManager, and Tokenomics. They use synthetic fresh or initialized storage and never send a chain transaction. The SessionKeyManager test also replays the exact initializer calldata from its archived deployment trace; its receipt shows the two matching events. Its [archived creation state diff](deployment_state_diffs.md) verifies the created proxy code and all six proxy storage writes. The [replay record](../../artifacts/remaining_initializers_local/replay.json) pins all four runtime hashes and the test source. The [Staking](staking_initializers_behavior.json), [SessionKeyManager](session_initializer_behavior.json), and [Tokenomics](tokenomics_initializer_behavior.json) ledgers hold the tested branches.

| Runtime and selector | Exact-runtime result | Limit |
|---|---|---|
| Staking `0x0f71c8bc` | In fresh state, an arbitrary user gets `0xc031a0df`. The proxy admin succeeds with two addresses, writes owner to slot 15 and executor plus an initialization flag to slot 16, and emits `OwnerUpdated` and `AuthorizedExecutorUpdated`. A repeat gets `0x3f733c4f`. | Source function name and broader admin context remain unknown. |
| Staking `0xc0c53b8b` | Three-address calls from user and proxy admin in fresh state, and a user with slot-16 flag set, all revert with `0xb7b2509c` without a persisted state change or event. A [bytecode proof](legacy_initializer_stubs.md) shows every canonical, zero-value call reaches that fixed revert. | `initialize(address,address,address)` appears in the Guardian report and hashes exactly to this selector; the report source snapshot has not been matched to the live runtime. |
| SessionKeyManager `0x747b8a1c` | The archived proxy creation succeeded with `initialize(address,string,string,uint256,address)` and arguments owner `0xa1763a5ff94ebddd417cccb906622ec762ab2e29`, `"String"`, `"1"`, chain ID 999, Exchange `0x6cd5661646289fb6e65ea5c032310fded797d0a2`. Exact-runtime replay writes the initialization flag, domain separator, owner, and authorized caller to slots 0 through 3 and emits the two receipt events. Changing the caller, owner, authorized caller, or chain ID still succeeds in tested fresh states. Changing the name to `"Name"` or same-length `"StrinG"`, or version to `"2"`, returns `0xf50220aa`; a repeat returns `AlreadyInitialized()`. | The [pinned constant and compare proof](session_initializer_constants.md) establishes `"String"` and `"1"` on the fresh-state path; original source is unavailable. |
| Tokenomics `0x485cc955` | Fresh state accepts either user or proxy admin. The two addresses fill the owner field in slot 0 and the second address in slot 1; slots 5 through 8 receive four default mint parameters. The call emits `OwnerUpdated` and `MintParamsUpdated`. A repeat reverts with `AlreadyInitialized()`. | `initialize(address,address)` matches the exact selector hash and tested behavior; original source remains unavailable. |

These tests establish selected EVM branches only. The SessionKeyManager deployment success corrects the earlier fresh-state-only inference: its `0xf50220aa` result depends on input values. The Staking three-address selector has a report-backed, hash-matched `initialize(address,address,address)` name and a pinned bytecode proof that canonical, zero-value calls always revert.
