# Second older Exchange retry implementation

At block 48,902,346, the second older Exchange proxy uses implementation `0x93a8e8d647f6c1e7b0f9bf4bd86eff3a9f20c3fb`. The [historical upgrade trace](older_exchange_upgrade.md) shows it replaced original implementation `0x6f0e9deab8a4f21344e4c10a35db5027b02a67fa` at block 48,092,890. The original is byte-identical to the newest Exchange implementation after normalizing ten linked-library addresses. The replacement has the same 98 dispatched selectors but is 477 bytes longer. The decompiler omitted a reachable block after `PendingSweepCleared` in `finalizeSweep(address)`, so its nearly identical Yul output does not establish equivalent behavior.

The [exact-runtime comparison](../../scripts/atlas_older_exchange_variant.py) uses both pinned implementation runtimes, constructed Exchange storage, mocked factory and HyperCore reads, and a proxy mock that records the requested `sweepAllToExchange` arguments. Fourteen Forge cases assert return status, pending storage, last-sweep storage, emitted events, and proxy calldata, including first requests at and below the minimum. The [result](../../artifacts/deployer_scope/older_exchange_variant_replay.json) includes both runtime hashes and the test-source hash.

| Constructed retry state | Original and newest bytecode behavior | Pinned older replacement behavior |
|---|---|---|
| Stored and current spot both 10 USDC | Clears old pending, sends and records 10 USDC | Clears old pending, sends and records 9 USDC, leaving 1 USDC in the proxy |
| Stored and current spot 1 USDC plus 90,000,000 raw perp units | Sends and records 1 USDC spot plus the full perp amount | Sends and records 0.9 USDC spot plus the full perp amount |
| Stored and current perp 100,000,000 raw units, spot zero | Sends and records all perp, no spot | Same result |
| Stored spot 10 USDC, current spot 1 USDC | Finalizes and clears pending, with no retry proxy call | Same tested branch result |
| Constructed legacy pending and current spot both 0.1 USDC | Reverts `0x329c2b0f`, preserving pending | Emits `PendingSweepCleared`, clears pending, and returns without another proxy call |

First-request tests use `sweep(address)` with no pending word. Both original and replacement request the full 10 USDC spot balance at the exact `1,000,000,000` raw spot-equivalent minimum; the replacement also forwards a full `10,000,000` raw perp balance at that minimum. One raw spot unit below it reverts with `0x329c2b0f` and leaves no pending word or proxy call. These are exact-runtime calls with a mock proxy, so they prove the EVM request amount, not Core delivery or fee payment. The replacement does not reserve 1 USDC on the tested first request.

The replacement subtracts `100,000,000` raw eight-decimal spot units, equal to 1 USDC, from a positive spot retry before recording its pending amount and calling the proxy. The extra bytecode begins at PC `0x4a56` with a minimum check and contains the reserve constant at PC `0x4ad3`. The original retry tail at PC `0x4a2b` jumps back to the shared request path, which sends the entire observed amount. The replacement's observed reserve applies to retries, while the tested first-request path asks for the full balance. A full source-level or all-branch equivalence claim is not established.

## Post-upgrade signed close replay

A successful BatchExecutor transaction `0xd0406da67e146d63014205b5c6b6cb8ada4c870ea7ceab0d17d73f34d5a2e968` at block 48,102,995 called `0x2792e706` on the second older Exchange ten thousand blocks after its upgrade. The [archived transaction, call trace, receipt, prestate, and state diff](../../artifacts/deployer_scope/older_replacement_signed_close.json.gz) show a successful signed close through SessionKeyManager, Oracle, the linked library, and Tokenomics. All 11 captured contract runtimes match byte-for-byte with the pinned scope or manifest. The observed BBO of 823,140 and 823,150 yields midpoint 823,145. Both library calls match the independent integer PnL and settlement models, including adjusted profit 11,312.901993338376298518 internal units, a 2% profit fee, and equal fee halves.

[`audit_older_replacement_close_replay.py`](../../scripts/audit_older_replacement_close_replay.py) loads those exact runtimes and transaction-accessed storage into a local Forge EVM, supplies the observed BBO response, and submits the original BatchExecutor calldata from its original sender. The call succeeds with the archived output and reproduces all five receipt logs and all 11 changed contract storage words. The [replay ledger](../../artifacts/deployer_scope/older_replacement_signed_close_replay.json) pins the capture, generated test source, runtime hashes, library vectors, and match counts. `python3 scripts/audit_older_replacement_close_replay.py --run` executes Forge with local `solc`; default mode checks the saved result offline without either tool.

This verifies one real post-upgrade close, its accepted historical signature, observed Oracle midpoint, and accounting writes. The BBO response is supplied from the archived trace. The prestate tracer captures transaction-accessed storage, not all historical state. This case does not establish other replacement branches, adversarial signature rejection, sender nonce, or Core settlement.

Two [historical retry traces](older_sweep_retries.md) now show this replacement running behind its older Exchange proxy: full-balance sends of 11.5 and 10.5 USDC failed with the Core transfer-gas error, then 10.5 and 9.5 USDC retry sends executed, each with a 1 USDC Core fee and an equal Exchange user credit. One retry also used an external 1 USDC top-up helper. This is relevant to [PT-01](../../FINDINGS.md): the newest Exchange uses the full-balance retry path as deployed. A [cross-set local replay](pt01_existing_replacement.md) shows that the older replacement would queue reduced sends for the two newest pending words if installed behind that proxy, but does not establish a safe production upgrade or Core settlement. The two older cases do not establish the general Core fee rule or prove that the same reserve would recover the newest proxies. The older users' pending words were zero at the pin; the below-minimum case in the table is constructed legacy state. Other replacement function bodies and the first older Exchange library still need independent fund, accounting, price, signature, and admin review.
