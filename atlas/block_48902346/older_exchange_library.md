# First older Exchange linked library

At block 48,902,346, the first older Exchange implementation links library `0xac8ba1307815f74bd13d4d039c96f7b97e81aa49`. Its saved runtime is 5,873 bytes. The [offline verifier](../../scripts/atlas_older_exchange_library.py) checks the pinned runtime hash, the first Exchange proxy's implementation slot, 11 library dispatcher selectors, and the two older-only selectors referenced by that implementation. The later library has ten selectors. Nine are shared; the older library alone has `0xaa31b143` and `0xacbc814f`, while the later library alone has `0xef1a27a9`.

Heimdall 0.9.2 generated [Yul](decompiled/exchange_linked_library_old1_yul-decompiled.yul) and [Solidity-style](decompiled/exchange_linked_library_old1_sol-decompiled.sol) hints for the pinned library and [Yul](decompiled/exchange_first_old_yul-decompiled.yul) and [Solidity-style](decompiled/exchange_first_old_sol-decompiled.sol) hints for its Exchange implementation. Only trailing whitespace was stripped from the generated text. These are untrusted decompiler output. The Exchange hints miss reachable calls to `0xaa31b143`, which the historical traces prove occurred. The nine shared library case bodies appear identical in the generated Yul after replacing the embedded library self address and three `CODECOPY` data offsets. This is a lead, not bytecode equivalence or a full behavior proof.

## Historical signed closes

The [raw capture](../../artifacts/deployer_scope/older_exchange_library_close_traces.json.gz) contains call traces and successful receipts for six signed-close transactions from the first older BatchExecutor at blocks 47,503,223 through 47,721,622. They are positions 0, 4, 8, 12, 16, and 19 among 20 close-containing transactions in a saved [100-transaction explorer page](../../artifacts/deployer_scope/older_batch_recent_txlist.json.gz). The [behavior ledger](older_exchange_library_behavior.json) verifies 24 position pairs in their first older Exchange `closeBySig` calls. Each pair calls library `0x82296364` for two-word PnL and then older-only `0xaa31b143` for six-word settlement. The second PnL return is exactly the signed PnL passed into settlement, and the stored position margin is passed to both.

| Checked branch | Positions | Result |
|---|---:|---|
| Positive adjusted PnL | 15 | Both PnL words and all six settlement words match the existing integer models |
| Negative adjusted PnL | 6 | Same match, including split loss fees |
| Zero adjusted PnL | 3 | Same match, with zero settlement fee words |

All 24 saved older settlement calls have equal 2% rate inputs and a nonzero seventh input word. Their six outputs match the [later settlement model](exchange_library_pseudocode.md) when zero is inserted as that later function's fifth input. This establishes the sampled output relationship only. It does not establish equal storage writes, equal event meanings, unequal-rate behavior, or a zero seventh-word branch. Each successful receipt contains one `0x330ea55a...` topic per position, one `0x64afd02d...` topic per nonzero PnL, and one `0x789bd128...` summary topic; the sampled call-tracer logs match those counts. Their exact event signature preimages remain unverified.

## Older-only queue function

The five [local exact-runtime cases](../../artifacts/deployer_scope/older_exchange_library_local.json) call older-only `0xacbc814f` through a delegatecall harness with a constructed empty queue and next ID 1. With margin 500 and PnL 100, -100, or zero, it returns and queues 600, 400, or 500 respectively. The queue head, next ID, global and user totals, user links, node amount, and hash-checked `Enqueued(address,uint256,uint256)` log match each result. PnL -500 and -501 both return zero, create no node, and emit no log. These cases show a sampled saturating `max(margin + PnL, 0)` path. They do not establish the function's behavior with existing nodes, large inputs, or a historical call through the first Exchange. The implementation contains one `PUSH4` reference to this selector, but this capture has no execution of it.

The expanded [raw capture](../../artifacts/deployer_scope/older_exchange_queue_traces.json.gz) checks all 20 close-containing inputs in the saved 100-transaction BatchExecutor page. Their 22 successful close frames contain 136 positions. Every position calls `0x82296364` and then `0xaa31b143`; none calls `0xacbc814f`. All 136 paired PnL and settlement outputs match the integer models, across 68 profits, 33 losses, and 35 flat PnLs. All 136 settlement calls still use equal 2% rates and a nonzero seventh argument. The [expanded verifier and ledger](../../scripts/atlas_older_exchange_queue.py) save the transaction, receipt, and call trace for each case.

The same capture includes filtered opcode steps from a one-position historical close at block 47,572,843. The pinned Exchange runtime reads its position word at `keccak256(abi.encode(position_id, 10)) + 1`; the saved close input supplies position ID 398,819, and the trace confirms the calculated storage slot and loaded word. Opcodes at `0x369d` to `0x36a2` compute the queue condition as `(position_word >> 232) & 0xff`. The helper at `0x549d` jumps from PC `0x54a7` to the queue selector at `0x57a8` only when this condition is nonzero. The sample's byte and jump condition are both zero, consistent with its observed `0xaa31b143` call. A later signed-open fork replay identifies this byte as the `useDebt` position flag. The five constructed library cases test only the callee.

## Exact Exchange caller replay

The [archive-backed fork replay](../../scripts/atlas_older_exchange_queue_replay.py) starts at block 47,572,842, the block before the saved one-position close. It installs the exact historical bid and ask response at HyperCore precompile `0x080e`. The first replay uses the original signed BatchExecutor calldata and position word. Its full call tree, including inputs, outputs, and nested logs, matches the archived successful transaction; ordered logs match its receipt. The replay also checks that the local Exchange implementation and linked library bytes equal the pinned runtimes.

Only the byte at position storage bits 232 to 239 changes in the two controlled cases. The [raw replay](../../artifacts/deployer_scope/older_exchange_queue_replay.json.gz) saves call traces and contract storage diffs for all three cases.

| Position byte | Second library call | Result |
|---:|---|---|
| 0, historical | `0xaa31b143` settlement | Loss event, no new queue node |
| 1, constructed | `0xacbc814f` queue | Enqueues 929.340689752633531376 internal units as node 8,453 |
| 2, constructed | `0xacbc814f` queue | Same call, events, and storage effects as byte 1, apart from the position byte |

The queue amount equals the saved margin of 1,000 units plus the signed PnL of -70.659310247366468624 units. Both nonzero cases emit the hash-checked `Enqueued(address,uint256,uint256)` topic. Storage diffs show next ID 8,453 to 8,454, global and user queue totals increasing by the amount, user head and tail set to 8,453, and node 8,453 storing the user and amount. The settlement-only loss event is absent. The old `positions(uint256)` getter returns its eighth field as false for byte zero and true for bytes one and two; its ninth active field stays true before the close. These are exact Exchange-runtime executions under a constructed position flag, not historical executions of that flag. The signed-open replay below identifies the flag as `useDebt`. Other queue states, economic backing, and actual Core delivery remain unresolved.

To regenerate the local capture, start Anvil at block 47,572,842 with `anvil --fork-url "$PAPERTRADE_ARCHIVE_RPC" --fork-block-number 47572842 --port <free-port>`, then run `python3 scripts/atlas_older_exchange_queue_replay.py --local-rpc-url http://127.0.0.1:<free-port>` in another terminal. `python3 scripts/atlas_older_exchange_queue_replay.py` checks the saved capture offline.

## Signed debt lifecycle

The [eleven-case Forge fork test](../../artifacts/deployer_scope/older_exchange_debt_open.t.sol) starts at block 47,721,328, before a saved successful signed open at block 47,721,329. The saved open uses `useDebt=false`; its receipt succeeds, returns position ID 398,939, and its archived BBO response is 271,710/271,720. A saved successful close at block 47,721,622 later includes that same position and another position. The test installs that BBO response, asserts the exact historical Exchange, SessionKeyManager, and older linked library runtime hashes, registers one constructed session key, and signs the pinned EIP-712 open and close digests with the matching private key. No signature recovery or Exchange runtime is stubbed.

The [saved results and offline checks](../../scripts/atlas_older_exchange_debt_open.py) show that a valid `useDebt=true` open requires the user queue total in slot 19 to cover the margin. With no credit or one internal unit below the 25e18 margin, it reverts with raw `0x8e667356`. With a coherent 25e18 queue node, it consumes the full node, clears user/global totals and user head/tail, leaves the ordinary balance unchanged, and writes one in the position flag byte at bits 232 to 239. With 30e18 queued, it leaves 5e18 in the node and both totals. A second signed open cannot reuse the exhausted credit. Changing `useDebt` after signing fails with raw `0xc5045f22`; a valid non-debt open debits the ordinary balance and writes zero in the flag.

A signed close immediately after a constructed debt-funded open marks the position inactive and enqueues the full 25e18 margin at the flat BBO price. A `harvest(1)` call consumes the new node and credits 25e18 to the user ordinary balance. A direct `withdrawToCore(25_000_000)` then debits that balance to zero. The test checks the `CoreWithdrawal` event and a recording CoreWriter mock receives `sendRawAction(bytes)` with a 100-byte action for the user and 2.5 billion Core units. The HyperCore user-status and spot-balance precompiles are locally mocked with valid-shaped responses; the CoreWriter action is not evidence that HyperCore executed or delivered the withdrawal.

Two more signed-close cases change the mocked BBO after the debt-funded open. For this short position, a close midpoint of 271,615 gives adjusted PnL +0.331156061910525405 and queues 25.331156061910525405 units. A close midpoint of 271,815 gives adjusted PnL -0.690061277441436799 and queues 24.309938722558563201 units. The [saved Forge call trace](../../artifacts/deployer_scope/older_exchange_debt_open_forge_trace.txt.gz) includes the old library math and queue calls; the [offline behavior verifier](../../scripts/atlas_older_exchange_debt_open.py) independently recomputes both PnLs and checks `queued = margin + adjusted PnL`. These are two controlled prices, not a proof of all price, fee, or liquidation boundaries.

The first three descending 100-transaction BatchExecutor explorer pages contain 491 open payloads in 208 transactions. All 491 encode `useDebt=false`. A wider [event-guided historical search](older_debt_history.md) matched all 15,689 opens whose users had enough event-visible queue credit, across 4,611 archived transactions; all matching calldata has `useDebt=false` (four events have two same-flag matches). This is exhaustive within the observed `Enqueued`/`Harvested` eligibility set, but an unlogged queue-credit path would escape that filter. The debt-funded cases use constructed queue state and authorization, so no historical `useDebt=true` open or queue-funded close is proven. Other price and fee boundaries, actual Core delivery, and full older-set liabilities remain unresolved. Run `PAPERTRADE_ARCHIVE_RPC=<archive RPC> python3 scripts/atlas_older_exchange_debt_open.py --live` to regenerate the Forge result, or `python3 scripts/atlas_older_exchange_debt_open.py` for offline verification.

A [separate exact-runtime liquidity replay](older_settlement_liquidity.md) now covers the older settlement selector under zero, partial, exact, and fee-threshold LP bankroll values, including unequal gain and loss rates. One [historical close](older_settlement_liquidity.md) also matches the zero-available queue-gated enqueue branch in its call trace, receipt, and transaction storage diff. It also runs five signed closes through the full older Exchange under a controlled treasury-slot override. The first older library still needs coverage for other fund and queue branches, including existing-node behavior and attacker reachability of tight bankroll states. Full older-set liabilities, Core settlement, other price and signature branches, and privileged control remain outside this narrow comparison. The newest Exchange and its linked library have separate [coverage](exchange_library_pseudocode.md).
