# Two historical older Exchange sweep recoveries

The second older Exchange received its [replacement implementation](older_exchange_upgrade.md) at block 48,092,890. Its complete [event history](older_accounts.md) contains exactly two `PendingSweepCleared` events. In both cases a first request converted 0.5 USDC from perp to spot and queued a full-balance spot send. HyperCore's public explorer reports `Insufficient USDC balance for token transfer gas.` for that send. The next EVM transaction cleared the pending request and queued a send reduced by exactly 1 USDC. Both reduced sends executed and both users were credited on the following EVM block.

| Proxy | First request | Rejected send | Retry block | Delivered | Core fee | Exchange credit | Spot at pin |
|---|---:|---:|---:|---:|---:|---:|---:|
| `0x5fa0a115d5f6f56d1b1c7f1df51d88adcb860a6d` | 48,092,958 | 11.5 USDC | 48,092,959 | 10.5 USDC | 1 USDC | 10.5 internal USD | 0 USDC |
| `0x07d38b03587edade651ee1520dfb619809992337` | 48,154,938 | 10.5 USDC | 48,154,939 | 9.5 USDC | 1 USDC | 9.5 internal USD | 1 USDC |

The [capture and verifier](../../scripts/atlas_older_sweep_retry_history.py) pairs the event history with three archived EVM transaction receipts and call traces per case, both finalization storage diffs, historical implementation slots and runtimes, public Core explorer execution records, and the already saved [proxy Core ledgers](../../artifacts/deployer_scope/older_proxy_core.json.gz). At each retry, the Exchange implementation slot points to the replacement, and its archived code plus the user proxy's archived code match their pinned runtimes. The first EVM request calls CoreWriter action 7 for 0.5 USDC and action 6 for the full amount. The retry calls the proxy with one fewer USDC and queues action 6 for that reduced amount. The finalization storage diff adds exactly the delivered amount to the user's balance, `treasury`, and the low word of `totalBalances`, then clears pending storage. The corresponding public Core ledger charges exactly 1 USDC on each delivered retry.

The second retry is wrapped in a call to `0x1b975d2b182ae23d8049fb28fbb19bbfd35e5cc6`, which is outside the captured Papertrade deployer set. Its EVM trace queues a 1 USDC CoreWriter spot send to the user proxy before calling the Exchange's `sweep(address)` path. The public Core explorer reports that top-up executed in the same Core block as the proxy's 9.5 USDC send, and the proxy ledger contains both transfers. The 1 USDC top-up accounts for the proxy's residual 1 USDC at the pin. The capture does not establish that the top-up was needed for the retry to succeed, or the precise intra-block order of the two Core executions.

These two live transactions validate the replacement's 1 USDC retry reserve in the observed states. A [38-proxy fee comparison](core_spot_fee_cohort.md) finds that they were the only two 1 USDC-fee sends among 112 older proxy-to-Exchange spot transfers. They do not establish a general HyperCore transfer-fee rule. [Hyperliquid's activation-fee documentation](https://hyperliquid.gitbook.io/hyperliquid-docs/for-developers/api/activation-gas-fee) describes a separate one-time new-account condition; the saved evidence does not attribute these two fees or [PT-01](../../FINDINGS.md) to that documented rule. The newest Exchange still runs the full-balance path and cannot use this older replacement to clear its pending requests. The public Core API responses are not cryptographic state proofs.

Run `python3 scripts/atlas_older_sweep_retry_history.py` to verify the compressed [capture](../../artifacts/deployer_scope/older_sweep_retry_history.json.gz) offline. To refresh it, set `PAPERTRADE_ARCHIVE_RPC` to an archive HyperEVM endpoint and run the script with `--capture`; the refresh also calls the public Core explorer.
