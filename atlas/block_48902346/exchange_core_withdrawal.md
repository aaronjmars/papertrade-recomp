# Exchange signed withdrawal to HyperCore

The [withdrawal ledger](exchange_core_withdrawal_behavior.json) checks three successful `withdrawToCoreBySig(address,uint256,uint256,uint64,uint8,bytes32,bytes32)` calls (`0x8d09f23f`). The name and ABI types reproduce the live selector. `CoreWithdrawal(address,uint256,uint256)` reproduces the observed event topic (`0x95d1a939...`). The event indexes the user and stores the internal debit and amount sent to HyperCore as two unindexed words.

| Sample | Internal balance debit, 18 decimals | Core amount, 8 decimals | Same-transaction credit |
|---|---:|---:|---:|
| Historical batch | 200 | 199 | 0 |
| Recent batch 1 | 11.429048 | 11.429048 | 0 |
| Recent batch 2 | 18.27 | 18.27 | 2.600758441858681628 staking reward |

In all three calls, the signed second argument is a 6-decimal raw amount. Multiplying it by 100 gives both the event's Core amount and the final 8-byte amount in the 100-byte CoreWriter payload. The payload also contains the event's indexed user. The event's first amount reconciles with the user's Exchange balance mapping at base 9. In the third batch, a `creditStakingReward(address,uint256)` call credits the same user, so the transaction's net balance change equals reward credit minus withdrawal debit.

The [expanded signed-call corpus](exchange_withdrawal_trace_corpus.json) checks 103 calls in 35 saved transactions, including four paired historical traces and 99 stratified call-only traces. Each call has exactly one account-existence read at `0x0810`, one Exchange spot-balance read at `0x0801`, one CoreWriter spot send, and one `CoreWithdrawal` event present in the complete event history. All 43 false existence results have a one-USD extra debit; all 60 true results have none. The four paired traces have saved receipts. The other 99 have callTracer event logs matched to the complete history but no saved storage diffs.

The historical batch debits 200 internal units while sending 199 to Core. The two recent batches debit and send equal normalized amounts. A [full-event census](exchange_withdrawal_event_census.json) checks all 28,643 `CoreWithdrawal` logs through the pinned block: 22,652 debit exactly the sent amount, and 5,991 debit exactly one USD more. No other gap occurs in those logs. Thirty-two signed-call traces, selected evenly across both gap classes, match each event to its Exchange call and nested HyperCore `coreUserExists(address)` read at `0x0810`, identified by [independent first-party protocol source](hypercore_user_exists_evidence.json). All 16 status-0 calls have the one-USD extra debit; all 16 status-1 calls have no extra debit. Two historical direct Safe calls and four exact-runtime local tests independently show the same split. The full event history does not expose user status, so status correlation is proven for the 103 saved signed calls and two direct calls, not every event. The [signature ledger](exchange_withdrawal_signature_behavior.json) independently rebuilds the EIP-712 struct hash and digest for all 103 selected signed calls. Each call passes the same user, nonce, and deadline to `consumeNonce`; SessionKeyManager receives the recomputed struct hash and signature, and ECRECOVER receives the recomputed digest. Every returned signer equals the withdrawal user. The [archive nonce ledger](withdrawal_nonce_history.json) checks bitmap storage at the block before, the withdrawal block, and the pin for all 103 sampled calls: each bit changes from unset to set and remains set. The 99 call-only traces still lack transaction-level storage diffs. A separate [26-case exact-runtime local audit replay](../../artifacts/audit_signed_intent_failures/replay.json) now checks invalid and tampered signatures, nonce rollback, a successful synthetic withdrawal, and next-block replay rejection under mocked HyperCore reads. CoreWriter submission is visible in the EVM trace; HyperCore settlement is a separate step. A [public Core ledger capture](../../artifacts/audit_withdrawal_settlement/public_ledger.json), verified against EVM receipts by [`audit_withdrawal_settlement.py`](../../scripts/audit_withdrawal_settlement.py), confirms delivery for one sampled signed new-account withdrawal and one signed existing-account withdrawal, plus two direct calls. The new-account signed case delivered 199 USDC with a 1 USDC Core fee matching its 200 USD internal debit; the existing-account case delivered 18.27 USDC with no fee and no extra debit. This four-case Core sample does not prove the full 28,643-event history.

The [getter ledger](exchange_getters.md) also hash-verifies `lastCoreWithdrawalBlock(address)` (`0x32faa570`). All three sampled withdrawals write that user's mapping-base-34 word to the transaction block, and archived calls return the new block. A fourth earlier withdrawal confirms the same write. Whether other withdrawal rules use this block value remains open.
