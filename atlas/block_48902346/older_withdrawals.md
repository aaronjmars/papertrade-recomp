# Older Exchange withdrawals through block 48,902,346

The [withdrawal census](../../artifacts/deployer_scope/older_withdrawal_logs.json.gz) checks 80 contiguous archive `eth_getLogs` windows, from each older Exchange's creation block through the pin, for the hash-verified `CoreWithdrawal(address,uint256,uint256)` topic. The [offline verifier](../../scripts/atlas_older_withdrawals.py) checks each log's emitter, topic, user, amount words, block range, and unique transaction and log index. Every indexed user belongs to that Exchange's captured factory-proxy cohort.

For all 33 events, the [public Core ledger capture](../../artifacts/deployer_scope/older_withdrawal_core.json.gz) finds exactly one matching `spotTransfer` in both the older Exchange sender's ledger and the indexed user's recipient ledger within the event block's one-second timestamp interval. The two API records are equal and have 33 distinct Core hashes. Each transfer's USDC amount equals the event's eight-decimal Core amount. The one extra internal debit matches a 1 USDC Core transfer fee; the other 32 have zero recorded USDC fee. This establishes delivery for these observed events to the extent that the public Core ledger API is complete and accurate. It does not prove that every possible withdrawal path emitted this topic, or that all remaining Exchange internal credits are currently redeemable.

The [three saved transaction traces](../../artifacts/deployer_scope/older_withdrawal_traces.json.gz) check one first-set signed withdrawal, one second-set signed withdrawal before its Exchange upgrade, and the second set's direct withdrawal after the upgrade. For each transaction, the receipt contains the exact census event; the call trace delegates through the Exchange proxy to its then-installed implementation, reads the Core account status, and calls CoreWriter with a 100-byte action for the event user and amount. Archive `eth_getCode` hashes at the transaction block match the pinned proxy and implementation runtimes, and the EIP-1967 slot matches the call target. The saved prestate diff shows the user's balance mapping at base slot 9, treasury at slot 14, and the low 128 bits of `totalBalances` at slot 22 each falling by the exact event debit. The two signed calls see an existing Core account and have no extra debit; the post-upgrade direct call sees a new Core account and debits 9.5 internal USD to deliver 8.5 USDC with the recorded 1 USDC fee. The 30 other events have event and Core-delivery checks but no saved storage diff.

That direct recipient is the user linked to second-set proxy `0x07d38b03587edade651ee1520dfb619809992337`, whose separate public Core ledger ends with 1 USDC and whose pinned Exchange balance getter is zero. The direct withdrawal trace accounts for the user's 9.5 internal USD debit and 8.5 USDC delivery; it does not explain or recover the proxy's residual 1 USDC.

The census is specific to these two Exchange proxies and this event topic through the pin. Public Core API records are independent settlement evidence, not cryptographic historical Core state proofs. The much larger pinned Exchange `totalBalances()` values remain internal accounting figures whose full account distribution and redemption semantics have not been established.

Run `python3 scripts/atlas_older_withdrawals.py` from the repository root to verify all saved evidence offline. To refresh it, set `PAPERTRADE_ARCHIVE_RPC` to an archive HyperEVM RPC URL and run `python3 scripts/atlas_older_withdrawals.py --capture-logs --capture-core --capture-traces`.
