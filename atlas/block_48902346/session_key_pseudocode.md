# SessionKeyManager registration and nonce paths

This map uses the live proxy at `0x8326eb8896e358717f10502ec73ce8d28e37b108` at HyperEVM block 48,902,346. The [behavior ledger](session_key_behavior.json) checks ten recent registrations, 19 nonce-consumption calls with storage evidence, 146 signed close/withdraw nonce inputs, 57 previously checked trading-signer calls, pinned getters, three historical management actions, 12 management and nonce branch probes, 10 session-signer input probes, 5 session-key storage overrides, and 6 direct-signer probes. It is reconstructed behavior, not original Solidity source.

The [direct getter checks](session_direct_getters.md) hash-verify five further names against pinned storage and archived outputs.
The [typehash ledger](session_typehash_behavior.json) verifies three constant getters against pinned outputs and `PUSH32` literals in the live runtime. `WITHDRAW_TO_CORE_TYPEHASH()` hashes `WithdrawToCore(address user,uint256 amount,uint256 nonce,uint64 deadline)`. `CLOSE_TYPEHASH()` hashes `Close(address user,uint256[] positionIds,uint256 nonce,uint64 deadline)`. `OPEN_POSITION_TYPEHASH()` at selector `0x6525a680` hashes `OpenPosition(address user,uint32 instrumentId,bool isLong,uint128 size,uint32 leverage,bool useDebt,uint256 nonce,uint64 deadline)`. The field-name lead came from the independent [Papertrade SDK source](https://github.com/nirholas/papertrade-sdk/blob/483a760ef596564e5ad799357a92e5726dada9ba/src/typed-data.ts); every resulting hash was checked against the pinned runtime constant. All three getter names hash to their live selectors.

## Storage

- `sessionKeys[user][key]` uses nested mapping base slot 4. The observed word packs a `uint64` expiry in bits 0:64 and a signed associated address in bits 64:224. The purpose of that address is unresolved. `sessionKeys(user,key)` returns those two fields as separate 32-byte words; selector `0xc1e6613d` returns the associated address alone, but its source name remains unknown.
- `nonces[user]` uses mapping base slot 5. Observed writes advance it to `nonce + 1` when the supplied nonce reaches or exceeds its earlier value.
- `nonceBitmapWord[user][nonce >> 8]` uses nested mapping base slot 6. Bit `nonce & 255` marks a used nonce. Both `nonceBitmapWord(address,uint256)` and `isNonceUsed(address,uint256)` agree with pinned raw storage for 19 sampled calls.
- `authorizedSubmitters[caller]` uses mapping base slot 7. A saved owner call set the BatchExecutor address to true before the sampled registrations. Slot 2 holds the owner; slot 3 holds the authorized Exchange caller.

## Registration

`registerSessionKeyBySig(address,address,uint64,address,uint256,uint64,uint8,bytes32,bytes32)` is selector `0x5f76a1d6`. Its nine calldata words in the ten samples are `user`, `key`, `expiry`, `associatedAddress`, `nonce`, `deadline`, `v`, `r`, and `s`.

```text
require authorizedSubmitters[msg.sender]
require an unused nonce and a valid deadline
structHash = keccak256(abi.encode(
    REGISTER_SESSION_KEY_TYPEHASH,
    user, key, expiry, associatedAddress, nonce, deadline
))
digest = keccak256(0x1901 || DOMAIN_SEPARATOR || structHash)
require ecrecover(digest, v, r, s) == user
mark nonce bit and, when needed, advance nonces[user]
sessionKeys[user][key] = pack(expiry, associatedAddress)
emit SessionKeyRegistered(user, key, expiry)
```

The typehash is `0xd3d9a309f635415423ab81e7e3fb16d2117cc8e1edc90506adde9eaa3855edd2`; the domain separator at the pin is `0x53a2ab5a64b3239d36b108fb4cd035ebb40ed3f71dec28e37966622670147e77`. All ten saved ECRECOVER inputs match this formula, recover the calldata user, emit the user/key/expiry fields, set the expected session word, and set the nonce bit. The [prior-block read-only replay](session_direct_getters.md) also shows that clearing the authorized caller changes the dynamic domain and makes one saved registration fail with hash-verified `InvalidSignature()`, despite its unchanged cached slot-1 hash. The exact EIP-712 type string and the associated address's purpose remain unresolved. An outsider registration reverted with `UnauthorizedSubmitter()`; replaying a saved registration from the authorized BatchExecutor at the pin reverted with `InvalidNonce()`.

## Exchange nonce use and revocation

`consumeNonce(address,uint256,uint64)` is selector `0xb002b9fa`. The saved calls came from Exchange, passed `user`, `nonce`, and `deadline`, and set the corresponding bitmap bit. An outside caller reverted with `UnauthorizedCaller()`, an already used nonce with `InvalidNonce()`, and a past deadline with `ExpiredDeadline()`. A read-only call with an unused nonce and a future deadline succeeded.

Sixteen of 19 saved nonce calls committed their bitmap writes. Three returned inside Exchange calls that later reverted; their bitmap bits did not persist. The pinned `isNonceUsed` getter and transaction state diffs agree for all 19. This matters when reading an internal call trace: a successful child call can still be rolled back by its parent.

`revokeSessionKey(key)` deletes `sessionKeys[msg.sender][key]`. The saved user transaction cleared its packed word and emitted `SessionKeyRevoked(user,key)`. A read-only call from an unrelated address also succeeded and emitted the event for that caller's own empty mapping entry; it did not touch the user's key. The historical `transferOwnership(address)` call from the stored owner changed slot 2 to its address argument and emitted `OwnerUpdated(address)` with that value. Its selector hashes to `0xf2fde38b`. Historical authorized-submitter updates also match their events and storage writes. Owner-only controls rejected an outside caller in pinned simulations.

## Trading signer recovery

Exchange made 57 saved calls to selector `0x7f608253` with `(user, structHash, v, r, s)` across 24 successful transactions and 45 distinct user-signer pairs. The [expanded signer ledger](session_signer_expanded_behavior.json) checks every call. ECRECOVER received `keccak256(0x1901 || DOMAIN_SEPARATOR || structHash)` plus the supplied signature and returned the same address as SessionKeyManager. The recovered signer differed from the user in every call. Archived block-level `sessionKeys(user, recoveredAddress)` results showed an unexpired key in all 57 cases, expanding the prior 18 checked calls by 39. Ten [pinned read-only signer probes](session_signer_branches_behavior.json) add two successful calls and eight rejected inputs. The same valid session signature succeeds from Exchange and an unrelated caller. Changing the user or struct hash, invalidating `v`, zeroing `r` or `s`, and supplying a historical direct-user registration signature all revert with `SessionKeyNotAuthorized()` (`0xc5045f22`), whose name matches the error hash. Invalid `v` skips ECRECOVER; zero `r` and `s` reach it. The direct-user registration signature recovers the user but is still rejected by this selector, so that sample has no direct-user bypass. Five temporary storage overrides verify the key check: expiry one second before the pinned timestamp reverts with hash-matched `SessionKeyExpired()` (`0xda0700a2`), while expiry equal to or one second after that timestamp succeeds. Zeroing the key word reverts with `SessionKeyNotAuthorized()`. Changing only the packed associated address from zero to a nonzero address still returns the signer in this sample. The exact function name, other rejection branches, the associated address's use elsewhere, and precise same-transaction registry prestate remain open.

The [signed Core withdrawal signature ledger](exchange_withdrawal_signature_behavior.json) checks 103 selected successful `withdrawToCoreBySig` calls in 35 transactions. Each withdrawal's user, nonce, and deadline match the nested `consumeNonce` input. The struct hash rebuilt with the pinned `WITHDRAW_TO_CORE_TYPEHASH()` matches the direct signer input, and the EIP-712 digest matches ECRECOVER input. All 103 recovered signers equal the withdrawal user. The [archive nonce ledger](withdrawal_nonce_history.json) reads SessionKeyManager bitmap storage before and after each withdrawal block and at the pin. All 103 sampled bits are unset before, set after, and still set at the pin. The 99 call-only traces still lack transaction-level storage diffs; block-level reads do not isolate a transaction index within a block.

The [signed-close hash ledger](session_close_typehash_behavior.json) checks 43 successful `closeBySig` calls in 22 transactions. Their 49 position IDs occupy arrays of length one to three. Hashing the packed ID words reproduces every dynamic-array field in the struct hash; the resulting EIP-712 digest and signature match ECRECOVER input, and SessionKeyManager returns the same nonzero signer. A separate [26-case exact-runtime local audit replay](../../artifacts/audit_signed_intent_failures/replay.json) accepts a valid four-ID close signature in a constructed state with empty position slots and rejects a signature after only the fourth ID changes, rolling back its nonce. This checks the four-word array hash and signer boundary, not settlement of four active positions. The [trading nonce ledger](trading_nonce_history.md) checks all 43 sampled successful closes and 58 sampled opens against archived bitmap storage. The 73 successful intents persist their bits; all 28 rejected opens leave them unset. Twenty-seven rejected opens had a successful nested nonce call before their parent reverted, and one nonce call itself reverted. Other array lengths and historical session-key storage for every signer remain open.

The [signed-open hash ledger](session_open_typehash_behavior.json) checks 58 saved `openPositionBySig` calls in 13 transactions. It rebuilds every struct hash from the eight typed message fields and compares it to the nested SessionKeyManager call. Fifty-seven calls reach the session signer and have matching EIP-712 digest, ECRECOVER input, and recovered address. Thirty opens succeed, 27 revert with hash-verified `OiCapExceeded()` (`0x40f92143`) after signer recovery, and one reverts with `ExpiredDeadline()` (`0xf87d9271`) before signer recovery. The saved-trace sample includes failed batch intents that are absent from the successful-event ledger.

The distinct selector `0xd45167d0` has four saved Exchange withdrawal calls. The [direct-signer ledger](session_direct_signer_behavior.json) reproduces each `keccak256(0x1901 || DOMAIN_SEPARATOR || structHash)` digest from the input words, matches the exact `(digest,v,r,s)` sent to ECRECOVER, and checks that the returned signer equals the withdrawal user. Six pinned read-only calls also show that an unrelated caller receives the same signer, changing the struct hash recovers a different address, and invalid `v` or zero `r`/`s` returns the zero address without reverting. Invalid `v` skips ECRECOVER; zero `r` and zero `s` reach it. The exact source name, declared ABI types, and other signature edge cases remain unresolved.

## Remaining work

The exact source names and full behavior of selectors `0x7f608253`, `0xd45167d0`, and `0xc1e6613d` remain unresolved. The [archived proxy creation and local replay](remaining_initializers.md) establish a successful `initialize(address,string,string,uint256,address)` call at selector `0x747b8a1c`, its four storage slots, and both emitted events. Name and version restrictions are sampled, not exhaustively characterized. Selector `0x17a1678f` has a [bytecode-verified fixed-revert path](session_disabled_selector.md), but its source name remains unknown. The ten registrations are a recent sample; this map does not establish complete historical registration coverage or the safety of every signature path.

An [eleven-case historical open replay](../../artifacts/audit_historical_open_tamper/replay.json) adds a changed-user control on the same pinned SessionKeyManager runtime. With only the user word changed, the saved signature returns `SessionKeyNotAuthorized()`. Copying the original recovered signer's unexpired session-key word into the changed user's mapping does not rescue it: the changed EIP-712 digest recovers a different address, and both direct signer verification and the Exchange open reject. This is a local storage override on one archived prestate, not evidence of a historical registration or a claim about every user and signature.
