# Papertrade bytecode atlas

## Goal

Build a reproducible behavior map of Papertrade's live HyperEVM contracts. Pin one block, enumerate the deployed code and proxy relationships, recover interfaces and storage, then check important paths against historical execution and read-only replays. Treat unresolved paths as explicit work items.

## Pinned scope

- Chain 999, block **48,902,346**, 2026-10-18 21:02:21 UTC, hash `0xd92ca32fdafb483c8e83f71c0abdfe4fcb89235b4191d78751f29371340530ab`.
- [Manifest](atlas/block_48902346/manifest.json): 25 captured addresses for the newest connected suite, including eight EIP-1967 proxy and implementation pairs, ProxyAdmin, the three-signer multisig, timelock, three linked libraries, two Exchange implementation variants not used by the newest proxy, and one representative user deposit proxy.
- [Deployer scope](atlas/block_48902346/deployer_scope.md): the same deployer created 59 direct contracts across three sets. All retain code at the pin. Thirty-eight older direct contracts and 38 older factory-created user proxies are outside the newest suite manifest, and one older Exchange uses a later implementation variant at the pin. The [first earlier Exchange](atlas/block_48902346/older_exchange_clear.md) has a tested owner clear path absent from the newest Exchange. Its [older linked library](atlas/block_48902346/older_exchange_library.md) has 136 historically checked close calculations, five direct library queue cases, three exact Exchange caller replays, and eleven fork cases that follow signed `useDebt` open through flat, profit and loss closes, harvest, and a mocked CoreWriter withdrawal boundary. The [second earlier Exchange replacement](atlas/block_48902346/older_sweep_retries.md) reserved 1 USDC in two historical retries that delivered and credited users after their full-balance Core sends failed. The current behavior atlas does not cover the remaining older-set paths.
- [Factory instances](atlas/block_48902346/deposit_proxy_instances.json): 22,586 successful CREATE2 deployments through the pinned block. [All deployment events](atlas/block_48902346/factory_event_deployments.json) match the internal CREATE2 rows by transaction, block, and address; all 22,586 addresses reproduce from the event user and captured creation code.
- [Family derivation](atlas/block_48902346/deposit_proxy_runtime_derivation.md): deterministic captured CREATE2 initcode predicts the 1,646 byte runtime and SHA-256 hash of all 22,586 deployments from each event user. The prediction matches 41 family-sample runtime hashes, one additional fetched runtime outside that sample, the full historical CREATE2 output, and two pinned constructor simulations. Only 42 deployed runtimes were fetched directly at the pin.
- [Upgrade history](atlas/block_48902346/upgrade_history.json): all eight proxies have zero `Upgraded(address)` logs and the same implementation slot at creation and at the pin. The shared proxy runtime emits no upgrade log. Saved direct admin transactions and timelock logs also contain no upgrade execution, with source-completeness limits described in the [ProxyAdmin behavior map](atlas/block_48902346/proxy_admin_pseudocode.md).
- [Compiler metadata](atlas/block_48902346/compiler_metadata.json): all 25 runtimes include Solidity 0.8.24 metadata and an IPFS content pointer. The explorer lists no verified source for the 17 nonproxy contracts checked in [source verification](atlas/block_48902346/source_verification.json).
- [Suite sets and post-pin refresh](atlas/block_48902346/suite_sets.md): four sets exist, not three. Sets `earlier_1` (2026-08-02), `earlier_2` (2026-10-05) and `newest` (the docs' **contract set 1**) came from the manifest deployer; a second deployer `0x13cb7a200d081094d23ebf07f4d708410a9c488b` shipped the docs' **contract set 2** on 2026-10-20, after this pin. Its governance batch was scheduled at block 49,080,037 and executed at block 49,169,385, replacing three proxy implementations: Exchange `0x0a44049dbbb6b4762a6ba37aa0f7548c0b4a3723` (23,959 bytes, sha256 `fc7374f3969381160732fe98c5e3145e00c3f167f168d61d65bb4972e9a6b268`), SessionKeyManager `0x04b5ea4c…`, Tokenomics `0x7c0a72a7…`, with new library `0x583d0bd8…` and a BuilderRegistry. The other five proxies still point at their pinned implementations, so only those three runtimes are stale.
- [Post-refresh pin](atlas/block_49265286/repin.md): an additive second pin at block **49,265,286** (2026-10-23T00:12:11Z, `0x82c2900c25f8e980ff7159d18ebd70c428c4801c3e6fbac80460723d8eedb9c9`) describing the same suite as it stands after the contract-set-2 batch. It carries 30 addresses, five contracts the batch added, a decoded selector catalog for the five new runtimes (176 selectors: 26 added, 3 removed, 12 names unresolved), pinned state reads, and a runtime file for the new code only; unchanged runtimes are referenced into the baseline rather than duplicated, and every hash recomputes from a saved file. The baseline pin and its artifacts are untouched.
- [PT-01 live state](atlas/block_48902346/suite_sets.md#pt-01-live-state): at head 49,255,838 both pending sweep words are byte-identical to the pin, both Exchange balance words and `balances(user)` read zero, owner `reconcileSweepCredit` still reverts, and the public Core ledgers show no entry since the pin, so the 62.150916 USDC stays uncredited in the two proxies. `clearPendingSweep` is absent from the new Exchange too, and [recovery/Pt01Recovery.sol](recovery/README.md) delegates to an implementation the live proxy no longer uses, so that plan now needs re-deriving against `0x0a44049d…`.

The two later Exchange implementation deployments expose the same 98 selectors. Neither was installed behind the newest Exchange proxy at its deployment block or at the pin. One is installed behind the second earlier Exchange proxy at the pin, as shown by the [deployer scope capture](atlas/block_48902346/deployer_scope.md). Their equal-length runtimes differ only in ten linked library address bytes and Solidity metadata. The two linked 5,790 byte libraries differ only in their embedded self-address guard. The newest Exchange implementation is shorter and needs separate semantic comparison.
